客服系统按角色脱敏，可审计角色也被当成普通角色，整张表的手机号都被打了码，事后无法核对：客服只应看到打码后的手机号，获授权的主管应看到原值，审计员应能核对谁在何时看过哪个字段。脱敏规则必须按字段路径与角色双重匹配；未匹配到规则必须按最严格处理；已授权角色必须能看原值且留痕；脱敏必须保持格式不泄露长度以外的信息；规则冲突时最严格优先；批量脱敏各请求独立。不变量：任何未显式授权的角色都看不到原值；同一请求两次脱敏结果相同。

场景

客服台同时展示工单、订单和用户资料。不同角色访问同一份记录时，可见字段并不相同。主管为处理投诉可以查看完整手机号，客服只能看到保留前后段的号码，审计员事后需要核对哪些角色在什么时候查看过哪个字段。

规则与匹配

一条规则由字段路径、角色和策略组成，字段路径可以是单层字段，也可以是点分隔的嵌套路径，还可以使用通配路径。策略分为允许查看和脱敏两类。匹配时必须同时满足字段路径与角色，不能只凭其中一项命中。角色名按忽略大小写处理，首尾空白不参与匹配。

冲突与默认

同一字段可能命中多条规则。此时按最严格的结果处理，允许查看不能覆盖脱敏。没有命中任何规则时同样按最严格处理，不得把原值直接返回。通配规则只能作为兜底，不能越过更具体的字段规则。

脱敏格式

手机号保留前三段与后四位，中间用星号等长替换。邮箱保留首字符与域名，其余部分等长替换。身份证保留前四位与后四位。姓名保留首字符。其他文本按原长度替换。脱敏结果不能暴露原值内容，但应保留原有格式与长度，便于展示和核对。

审计

角色获得原值属于授权查看。每次授权查看都要产生一条审计记录，记录角色、字段路径和查看事件。审计记录必须可以被后续核对查询到，未授权角色不得产生授权查看记录。

批量

批量接口接收多个请求，每个请求包含角色和记录。请求之间互不影响，前一个请求的角色和匹配结果不得被后一个请求继承。同一请求重复执行应得到相同结果。

验收

公开测试用于确认基本契约，隐藏测试用于确认边界行为。实现应保证未显式授权的角色在任何路径下都无法取得原值。
